# Канвас оценки инициатив

Канвас заполняется первым, до карточек паспорта: он даёт вердикт по инициативе целиком, остальные разделы её раскрывают. По каждому полю — краткая формулировка. Вывод — "берём / берём с условием / не берём".

## Инициатива №1. Автоматически выявлять подозрительные операции по счетам (флагман)

| Вопрос | Что фиксируем |
| -- | -- |
| **Ценность** | Рост результативности проверок финмониторинга при том же штате (25 сотрудников разбирают ~10 тыс. из ~35 тыс. помеченных операций в месяц, очередь растёт). Прямой денежный эффект — это удержанные суммы. А также снятый риск претензий надзора (два предписания за прошлый год) |
| **Выполнимость** | Средняя: технологически решаемо (классификация + ранжирование), но есть сложность с метками и смещением отбора. Нужен гибрид с детерминированными правилами |
| **Данные** | Частично готовы: история операций за несколько лет есть, разметки "схема / не схема" нет, есть три разных по надёжности следа (эскалация ~400/мес, исход расследования, единицы формально подтверждённых спустя месяцы). Непроверенная операция не является чистой, она просто непроверенная. Нужен план работы с метками и смещением |
| **Риск** | Высокий: 115-ФЗ и ПОД/ФТ (это обязанность банка, а не инициатива), банковская тайна. ПДн. Ошибка двусторонняя: пропуск схемы — риск надзора, лишняя блокировка — потеря клиента (~600 приостановок/мес, ~450 снимаются после разбора, ~120 жалоб от клиентов, часть клиентов уходит в другой банк). Но автоматизированные решения, связанные с ПДн, — решаются с юристами и DPO |

**Вывод: берём с условием**  
Правовое основание обработки и допустимость автоматизированных решений подтверждают юристы и DPO. Метки и смещение отбора закрываются планом.

## Инициатива №2. Распознавать и оцифровывать сканы документов кредитной заявки

| Вопрос | Что фиксируем |
| -- | -- |
| **Ценность** | Сокращение времени андеррайтинга (сейчас полтора часа на пакет) и снижение доли ручного переноса полей. Выше качество извлечения — меньше ошибок в кредитном решении |
| **Выполнимость** | Высокая: OCR и LLM для извлечения полей — зрелые технологии. Основная сложность в разнородных форматах (Excel, PDF-сканы, выгрузки, фото с телефона) и качестве сканов |
| **Данные** | Хорошие: документы есть, возможна ручная разметка полей экспертами. Нужно выработать правила разметки и контроль согласованности |
| **Риск** | Средний: ПДн заёмщиков, представителей, поручителей. Банковская тайна. Ошибка извлечения ловится сверкой со справочниками и человеком. По правовым вопросам идти к DPO и юристам |

**Вывод: берём.**  
В отличие от флагмана — другой домен, другая модальность (документ/изображение), другой источник сигнала (ручная разметка, а не история). Инициатива кажется ценной и реализуемой, есть четкий источник сигнала.

## Инициатива №15. Прогнозировать нагрузку на кол-центр для планирования смен

| Вопрос | Что фиксируем |
| -- | -- |
| **Ценность** | Планирование смен под прогноз нагрузки. Можно получить меньше переработок и простоев, лучше соблюдение SLA ответа. Эффект измерим в человеко-часах и в соблюдении целевого времени ответа |
| **Выполнимость** | Высокая: прогноз временного ряда — стандартная задача, есть история обращений, инструменты и компетенции доступны |
| **Данные** | Хорошие: история нагрузки есть, источник сигнала — фактические обращения по часам/дням. Нужно проверить непрерывность и корректность временного ряда, учесть сезонность, праздники, выбросы |
| **Риск** | Низкий/средний: ошибка прогноза ведёт к неоптимальному расписанию, но не к юридическим последствиям. ПДн минимальны |

**Вывод: берём.**  
В отличие от других инициатив — другая операция (прогноз временного ряда), другая модальность, другие метрики (MAE/MAPE, а не precision/recall). Инициатива кажется выполнимой, с четким источником хороших данных, при этом с низкими рисками и даст измеримую ценность.
