# ADR-002. Распознавание и оцифровка сканов кредитной заявки: данные, размещение, модель

Статус: предварительное
Дата: 19.11.2026
Инициатива: №2. Распознавать и оцифровывать сканы документов, приложенных к кредитной заявке

## Контекст

Пакеты кредитных заявок: разные форматы (Excel, PDF-сканы, выгрузки, фото с телефона). Андеррайтинг разбирает пакет около полутора часов. Ценность — сокращение времени и доли ручных правок.

Ссылки: паспорт инициативы №2, разделы 1–5; канвас оценки.

## Жёсткие ограничения

- ПДн заёмщиков и поручителей-физлиц, банковская тайна, правовое основание, договор, регион обработки и хранения данных — к комплаенсу, DPO и юристам.
- Автоматизированные решения по ПДн — это к юристам, в этой постановке решение по заявке принимает человек.
- Кредитное решение — остаётся за андеррайтером, не за моделью.

## Сравнительные критерии

После отсечения по жёстким ограничениям сравниваем по:

- ценность/эффект (время разбора, доля ручных правок)
- выполнимость
- данные (разметка)
- стоимость владения
- риск (ПДн, качество на редких форматах)

## Рассмотренные варианты

### По размещению — пилот

| Вариант | Почему |
| -- | -- |
| Публичный API | Отклонён. Чувствительные данные в мультиарендном контуре. Для пилота на обезличенных данных технически возможно, но риск не оправдан |
| Существующая инфраструктура банка | **Выбран для пилота.** документы уже в контуре, разметка на обезличенных данных |
| Выделенный контур / self-hosting / on-prem | Избыточны для пилота |

### По размещению — прод

| Вариант | Почему |
| -- | -- |
| Публичный API | Отклонён. Не подходит по hard constraints (ПДн, банковская тайна) |
| Выделенный контур провайдера | Кандидат для LLM-звена извлечения полей, с договорными гарантиями (после ответа DPO и юристов) |
| Self-hosting / on-prem | Кандидат на позднюю стадию при росте нагрузки и наличии команды |
| Гибрид по звеньям | **Выбран для прода.** OCR/извлечение — в контуре банка или выделенном контуре. Сверка и инварианты — в контуре банка |

### По модели

| Вариант | Почему |
| -- | -- |
| Публичный рейтинг / флагман | Отклонён. Не про нашу задачу, для извлечения полей важнее дисциплина формата и честное "поля нет", чем "умность" модели |
| OCR + LLM для извлечения полей | **Выбран.** OCR — распознавание, LLM — извлечение полей со ссылкой на источник |
| Только OCR без LLM | Отклонён. Андеррайтер всё равно переносит поля вручную, эффект от решения минимален |
| Полное автозаполнение решения | Отклонён. Кредитное решение должно оставаться за человеком |

## Решение

- **Размещение:** пилот — на существующей инфраструктуре банка; прод — гибрид по звеньям (OCR/извлечение — в контуре банка или выделенном контуре, сверка — в контуре банка). Правовые аспекты решаются через DPO и юристов.
- **Модель:** OCR + LLM для извлечения полей; сверка и инварианты — код; решение — остается за человеком.

## Допущения

| Допущение | Источник | Критично для вывода |
| -- | -- | -- |
| Разметка полей согласована | Требует гайдлайна и оценки согласованности | Да |
| Качество на редких форматах достаточно | Проверяется на пилоте | Средне |
| Правовое основание обработки подтверждено | Ответ DPO и юристов | Да, блокирует запуск |

## Риски и что с ними делаем

- **Ошибка извлечения**: сверка со справочниками, инварианты, человек в петле.
- **Редкие форматы**: добрать примеров таких форматов.
- **ПДн**: минимизация, обезличивание, ответ DPO и юристов.
- **Lock на провайдере**: реализовать адаптер перед LLM-провайдером.

## План выхода

Адаптер перед LLM-провайдером.
Выполнить миграцию на другого провайдера или self-hosting при изменении цен/условий.

## Триггеры пересмотра

- изменение законодательства (ПДн)
- появление open-weight-модели, укладывающейся в требования
- изменение цен/условий у провайдера
- провал пилота по критериям остановки
