# Флагман: план пилота

## 1. Какие неопределённости проверяет пилот

Пилот проверяет не работоспособность модели, а экономические допущения, которые переворачивают решение.

| Неопределённость | Почему критична | Как проверяется | Критерий успеха |
| -- | -- | -- | -- |
| Правовое основание | Если нет — пилот невозможен | Ответ комплаенса/DPO/юристов должен быть получен **ДО** пилота | Получено положительное заключение |
| Результативность приоритизированной очереди vs текущей | **Главное допущение** — от него зависит весь эффект | В течение 2 недель эксперты работают с двумя очередями параллельно: (а) текущая очередь (отбор правилами/жалобами), (б) очередь от модели. Обе очереди **ограничены одинаковым бюджетом времени** (например, 4 часа в день на каждую). Оценка выполняется по **независимой экспертной разметке** (эксперт, не знающий, из какой очереди кейс, оценивает, является ли операция обоснованной эскалацией, которую стоит расследовать) | Доля обоснованных эскалаций в очереди модели выше, чем в текущей, **не менее чем на 10 п.п.** при одинаковом бюджете времени |
| Формальные подтверждения (с задержкой) | Это единственный сигнал, который в кейсе считается "настоящим" подтверждением схемы. Но они появляются спустя месяцы. Если пилот будет ждать только их, то он растянется на кварталы. Поэтому пилот не может опираться на них как на основной критерий, но обязан их отслеживать, чтобы потом сверить с обоснованными эскалациями | Отслеживаются отдельно, с учётом с учётом задержки. На пилоте фиксируем **предварительные** подтверждения, но основной вывод делаем по обоснованным эскалациям | **Отложенный критерий**. Предварительные подтверждения не противоречат картине обоснованных эскалаций. После появления достаточного числа формальных подтверждений (уже после пилота) — доля подтверждённых среди обоснованных эскалаций должна быть выше, чем среди текущей очереди |
| Доля кейсов, которые не могут быть обработаны | Если слишком высокая — система не помогает оператору | Считается долю `quarantined` (критичные нарушения контракта) и долю `ok_with_notes` с пометкой "признак недоступен" | Доля `quarantined` не выше 5%, доля `ok_with_notes` с пометкой "признак недоступен" не выше 10% (это у нас означает не "ручная проверка", а "сбой обработки") |
| Стоимость обработки на реальном потоке | Может быть выше расчётной | Замер на месячном объёме | Стоимость проверки не выше **x1.5 от расчетной** |
| Качество на новых сегментах | Модель может плохо работать на новых данных | Отдельный срез по недавно подключённым клиентам | Просадка на новом сегменте **не более 5 п.п.** относительно старых сегментов. При большей просадке сегмент исключается из автоматической приоритизации до дообучения |

## 2. Guardrails (что не должно ухудшиться)

| Guardrail | Порог | Кто следит |
| -- | -- | -- |
| Доля необоснованных блокировок | Не растёт выше текущего уровня (около 600/мес) | Руководитель финмониторинга |
| Время эксперта на один кейс | Не растёт | Руководитель финмониторинга |
| Доля пропущенных крупных нарушений | Не растёт | ML-команда + бизнес |
| Доля ошибок, найденных после подтверждения | Не растёт | Владелец сервиса |
| Количество жалоб клиентов | Не растёт | Бизнес |

## 3. Критерии остановки пилота

Пилот останавливается (и проект закрывается или пересматривается), если:

- **Не получено правовое основание** для работы с реальными данными в выбранном контуре.
- Результативность проверок **не выросла значимо** после устранения технических проблем.
- Доля кейсов, уходящих на ручную проверку, **настолько высока**, что экономии не возникает.
- Стоимость проверки **превышает эффект** на проверку.
- Guardrails **нарушены** и не восстанавливаются.

## 4. Четыре возможных решения по итогам пилота

| Исход | Решение |
| -- | -- |
| Результативность не выросла; правовое основание не получено | **Остановить проект** |
| Результативность не выросла, но есть другой эффект (например, снижение жалоб) | Пересмотреть целевой эффект и метрику |
| Результативность выросла, но доля ручной проверки слишком высока | Изменить постановку (например, сузить до крупных сумм) |
| Результативность выросла, guardrails в норме | Продолжить внедрение как есть |

## 5. Длительность и стоимость пилота

**Длительность:** 6-8 недель (включая подготовку разметки и правовые согласования).

**Кто участвует:**

- ML-команда: 2-3 человека (0,5 ставки ML-инженера на 2 месяца).
- Эксперты финмониторинга: 2-3 человека на разметку и оценку очереди (~40 часов на эксперта).
- Владелец сервиса: координация.
- Представитель комплаенса/юристов/DPO: правовое сопровождение.

**Стоимость пилота:**

| Статья пилота | Расчёт | Сумма | Источник / допущение |
| -- | -- | -- | -- |
| Разметка контрольной выборки | 3 000 операций × 150 р/операция | 450 000 р | **Оценка** ставки разметчика |
| Время ML-команды на пилот | 0,5 ставки ML-инженера × 230 000 р/мес × 2 мес | 230 000 р | **Аналогия** оплаты по рынку ML-инженера для поддержки |
| Время экспертов финмониторинга на оценку очереди | 3 эксперта × 40 часов × 937 р/ч | 112 440 р | Цена оценки экспертом **из кейса** |
| Инфраструктура на пилот | 1 инстанс × 40 000 р/мес × 2 мес | 80 000 р | **Оценка** (та же ставка, что в TCO, но без резерва под пик) |
| Правовое сопровождение (комплаенс/DPO/юристы) | 100-200 часов × 2 000 р/ч | 200 000 - 400 000 р | **Оценка** (данных нет, приблизительная оценка из критичности банковской сферы) |
| **Итого без резерва** | | **1 072 440 – 1 272 440 р** | |
| **Резерв на непредвиденное (20%)** | | **214 488 – 254 488 р** | Стандартная практика для пилотов, т.к. часть статей может сильно вырасти |
| **Итого с резервом** | | **1 286 928 – 1 526 928 р** | |

**Итог:** стоимость пилота — порядка **1,1-1,3 млн р** (без резерва), или с резервом 20% около **1,3-1,5 млн р**.

## 6. Условия успеха пилота (операционные)

Пилот отвечает на вопрос: **даёт ли ранжирование прирост обоснованных эскалаций на час эксперта?**

| Метрика | Как измеряется | Критерий успеха |
| -- | -- | -- |
| Обоснованные эскалации на час эксперта | Независимая экспертная разметка двух очередей (текущая vs модельная) при одинаковом бюджете времени | Прирост не менее 10 п.п. при одинаковом бюджете времени |

Пилот **не** отвечает на вопрос "сколько денег это принесёт" — формальные подтверждения появятся позже.

## Условия запуска в прод (экономические)

Запуск в прод требует подтверждения **денежного эффекта** на случаях, **по которым уже известен исход** (формальные подтверждения появились).

| Метрика | Как измеряется | Критерий |
| -- | -- | -- |
| Денежный эффект на подтверждённых случаях | Сравнение подтверждённых случаев из модельной очереди и текущей очереди **после появления формальных подтверждений** | Эффект перекрывает TCO (с учётом того, что сумма удержанного платежа не равно сэкономленные деньги (платёж мог быть возвращён, клиент мог оспорить, часть суммы — не прибыль банка). Поэтому для запуска в прод нужен аккуратный расчёт эффекта на подтверждённых случаях, а не просто "сумма удержаний" |
